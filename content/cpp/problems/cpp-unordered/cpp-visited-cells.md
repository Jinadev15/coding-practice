## Statement
A rover starts at `(0, 0)` on an infinite grid and executes `n` moves. Each move is a direction `U`, `D`, `L` or `R` and a step count `k`, and the rover visits **every cell** along the way. Coordinates can reach ±10⁹, so you can't use a 2D array.

Print:
1. `distinct D`: the number of distinct cells visited, including the start.
2. `revisits R`: the number of times the rover stepped onto a cell it had already visited.
3. `first_repeat X Y`: the first cell visited twice, or `first_repeat none`.

The total number of steps (the sum of the k values) is at most 2·10⁶. Store the visited cells in a `std::unordered_set` with **your own hash** for the coordinate pair: `std::pair` has no `std::hash`. Pack `(x, y)` into one 64-bit key and mix it with a strong hash (SplitMix64), and `reserve` the table up front.

## Starter
```cpp
#include <iostream>
#include <unordered_set>
#include <cstdint>

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int n;
    std::cin >> n;
}
```

## Hints
- Pack: `std::uint64_t key = (std::uint64_t(std::uint32_t(x)) << 32) | std::uint32_t(y);`. The casts through `uint32_t` keep negative coordinates distinct.
- SplitMix64 is a few xor-shifts and multiplies, and spreads structured keys (neighbouring cells) uniformly over the buckets.
- `insert(key).second` is `false` exactly when the cell was already there: a revisit.

## Solution
```cpp
#include <iostream>
#include <unordered_set>
#include <cstdint>

struct SplitMix64 {
    std::size_t operator()(std::uint64_t x) const noexcept {
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return static_cast<std::size_t>(x ^ (x >> 31));
    }
};

static std::uint64_t pack(long long x, long long y) {
    return (static_cast<std::uint64_t>(static_cast<std::uint32_t>(x)) << 32) | static_cast<std::uint32_t>(y);
}

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);
    int n;
    std::cin >> n;
    std::unordered_set<std::uint64_t, SplitMix64> seen;
    seen.reserve(1 << 22);
    long long x = 0, y = 0, revisits = 0;
    bool have_repeat = false;
    long long rx = 0, ry = 0;
    seen.insert(pack(0, 0));
    for (int i = 0; i < n; ++i) {
        char d;
        long long k;
        std::cin >> d >> k;
        long long dx = d == 'R' ? 1 : d == 'L' ? -1 : 0;
        long long dy = d == 'U' ? 1 : d == 'D' ? -1 : 0;
        while (k--) {
            x += dx;
            y += dy;
            if (!seen.insert(pack(x, y)).second) {
                ++revisits;
                if (!have_repeat) { have_repeat = true; rx = x; ry = y; }
            }
        }
    }
    std::cout << "distinct " << seen.size() << "\nrevisits " << revisits << '\n';
    if (have_repeat) std::cout << "first_repeat " << rx << ' ' << ry << '\n';
    else std::cout << "first_repeat none\n";
}
```

- **Packing** two 32-bit coordinates into one `uint64_t` gives a key whose equality is exact and cheap, and that's trivially hashable.
- **SplitMix64** matters because `std::hash<uint64_t>` is the identity in libstdc++. With identity hashing, keys `x << 32 | y` that differ only in high bits all land in the same bucket modulo many bucket counts, degrading towards O(n) per operation. A mixing hash avoids that.
- **`reserve`** sizes the bucket array once, avoiding repeated O(n) rehashes while 2 million cells are inserted.
